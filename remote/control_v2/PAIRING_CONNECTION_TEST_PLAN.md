# ScreenSync Beta4 — 设备配对与连接正确性验收

> Beta4 实验分支。此文档说明新增的安全约束，不表示日本 VPS / Xiaomi / vivo 已经通过真机验证。严格只读屏幕传输也尚未实现，现有 ADB + scrcpy 仍有高权限。

## 身份优先：不能根据 IP 决定是哪部手机

1. 主手机通过管理员一次性二维码开通，生成最多 5 分钟的邀请；另一台扫描并主动提出配对申请。
2. 双方需要核对屏幕上相同的 **6 位申请核对码**。主手机必须亲自确认。不一致时应拒绝，不能凭手机名称相似就允许。
3. 服务器把 `group_id`、各自 `device_id`、WireGuard `device_public_key`、`peer_device_id`、`peer_public_key` 与 `device_ip`、`peer_ip` 绑定返回到已认证的 HTTPS `/v1/status`。
4. Android 客户端核对本机已注册的设备 ID/公钥；拒绝错误配对组、未授权设备、两个设备使用同一 IP、Beta3 `100.80.*` 地址。
5. 客户端每次观看前重新获取当前服务器状态，并用保存的组密钥与**精确目标 VPN IP** 进行双向 HMAC 挑战认证。没有通过 HMAC 就不能探测或连接 ADB。
6. 经过相互验证后才使用目标当前自己报告的 ADB 端口；旧端口、局域网广播/mDNS 任意结果、历史 DHCP 地址都不是可靠凭证。
7. Android 仅在双方允许、完成系统 VPN/ADB 授权后建立连接。不得绕过 Android 的系统授权提示。

## 两种连接路径必须严格分开

- **Beta4 服务器注册状态存在时**：只能使用服务器绑定的 WireGuard IP。VPN 关闭、服务器不可访问、身份不一致时，显示明确错误，**不得退回 LAN、旧 Beta3 IP 或保存的端口**。
- **旧局域网配对兼容模式**：二维码仅使用系统确认存在的活动 Wi-Fi IPv4，不从随意的网卡或开启的 VPN 猜地址。连接旧 IP 前也先要求接收端双向 HMAC 证明。DHCP 变化后，可通过 mDNS 寻找候选 IP，但只有真正通过 HMAC 的候选才可用于 ADB。
- 配对组内的 WireGuard IP 由服务器分配并持久化，运营商/NAT/Wi-Fi/移动网络变化不应改变设备身份、配对组或组密钥。

## 部署前负面回归用例

| 模拟情况 | 预期 |
|---|---|
| A/B 同局域网，A 获得新 DHCP 地址 | 旧 IP HMAC 失败，验证到新 IP 的身份后才连接；不能仅凭 IP/名称连错 |
| B 使用旧 IP，已分配给不相关的 C | 不允许直接查询 C 的 ADB；只有通过原配对 HMAC 的设备才被接受 |
| 双方在不同运营商网络，存在不同内网 192.168.x.x | Beta4 只使用服务器绑定的 100.81.x.x，不引用各自 LAN IP |
| A 的 VPN 尚未启动或系统返回其他 VPN IP | 不自动选择相似地址；提示 VPN 尚未就绪 |
| A/B 拿到不同的 6 位配对核对码 | 主手机拒绝申请，不能强行配对 |
| 客户组 1 的手机扫描客户组 2 的信息 | 不可跨组审批，服务端 nft 不允许跨组互通 |
| 被配对手机换机或设备密钥变化 | 本机 ID/公钥不一致或 peer_id 变化时禁止自动覆盖，要求本人重新确认 |
| 当前 ADB 端口变更、旧端口继续由其他进程监听 | 只从经过 HMAC 身份验证的当前设备获取端口，不能拿旧端口直接连接 |
| 服务器撤销配对，客户仍有旧缓存 | HTTPS status 被拒绝，客户端无 LAN 降级；内核 ACL 撤销，不能恢复旧访问 |
| Beta4 VPN 启动前只有旧 Beta3 .conf 文件 | 在开启 VPN 前验证注册状态并应用对应的专属新配置，不得连接旧隧道 |
| 弱网、系统返回 VPN UP 但 IP 尚未出现 | 有限次重试同一经认证的 VPN 地址，不扫描或猜其他手机 |
| 两台 Android 手机重启/划走后台 | 系统允许时恢复连接，但需要现场验证 Android 厂商后台限制，不能保证永久自动唤醒 |

## 自动化验证与剩余真机验收

- Java JVM 单元测试：`TrustedPairEndpointTest`，覆盖错误/过期/格式错误 IP、旧地址段、不同本机和 peer IP、服务端目标 IP 与对方返回 IP 不一致、端口缺失。
- Python localhost HTTP 测试：两个组的注册、一次性邀请码、双方六位核对码相同、peer/device/group ID 绑定和撤销。
- 临时 Linux WireGuard + nft + systemd 测试：两组物理隔离、解绑断流、异常停止阻断、重启只恢复获授权配对。
- 下一阶段：使用真实小米/vivo 手机分别连接不同 Wi-Fi/蜂窝网络，验证 Android 厂商网络接口可见性、ADB 在 VPN 上的可达性、权限保持、主动断开、重启和网络切换。

**不可发布条件：** 当前 ADB + scrcpy 不能被描述成严格只读的客户观看服务；需采用受限视频传输及被观看方明确授权、可撤销的机制并完成真机安全评估。

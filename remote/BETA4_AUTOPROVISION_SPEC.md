# ScreenSync Beta 4 — 安全自动异地连接实施方案

> 状态：仅为实施方案，**不是已完成的功能**。Beta 3 仍需手动导入 WireGuard 配置文件。此分支不得在下述验收完成前当作正式版发布。

## 用户体验（目标）

1. 两台 Android 手机安装同一个 ScreenSync APK。无需另装 VPN 软件、导入 `.conf`、填写服务器 IP 或端口。
2. 手机 A 生成二维码，B 扫码；A、B **分别明确同意**配对和远程观看权限。
3. App 在安全网络连接下自动获取**各自独立**的 WireGuard 配置，显示系统标准 VPN 授权并允许拒绝；始终保留明显的「断开观看」「关闭异地网络」「解绑」。
4. 点击「立即观看」时尝试启动本机授权 VPN，再尝试已经授权过的 ADB+scrcpy **只读**镜像。无线调试被系统关闭、授权失效或目标手机系统不支持时，明确报错而不是无限等待。
5. 首次配对可以从不同互联网网络发起；不得依赖同一 Wi-Fi 的 mDNS/内网地址完成远程首次配对。现有 LAN 功能在新功能通过验证前不删除。

## 已核对代码

- `app/src/main/java/org/client/scrcpy/EmbeddedRemoteTunnel.java`：官方 WireGuard GoBackend，当前读取内部 `screensync_private_vpn.conf`，从 `importConfig()` 保存到私有目录。
- `MainActivity.java`：`remote_vpn_setup_button` 触发 ACTION_OPEN_DOCUMENT 文件选择，`startOneTapWatch()` 可在存在配置时启动 VPN。
- `OneTapConnection.java`：优先 Overlay IP，依赖已保存的 peer / ADB 授权；不能将 VPN 握手等同于镜像已成功。
- `PairQrCode.java`：当前二维码面向 LAN/overlay，首次跨网扫码仍需新增服务端协调机制。
- `remote/setup_wg_vps_ubuntu.sh`：仅创建两个客户端静态 `.conf`，并非设备注册服务。不可把生成的客户端私钥放入 APK。

## 建议的安全架构

### 控制层：HTTPS 注册 / 双方批准 / 配对管理

- VPS 上部署独立受限的 TLS 端点。优先使用专用子域名与有效证书；服务端认证/校验证书为强制项，不接受明文 HTTP 或忽略 TLS 错误。
- App 在设备本地生成唯一 WireGuard 私钥，**仅向服务器提交公钥**；本机持久保存私钥到不可备份的应用私有存储。
- 首次注册创建独立设备身份与认证凭据。短时有效的扫码邀请由服务器生成，B 申请后 A 显式批准，B 再确认；邀请码只能使用一次且不能授予 ADB。
- 服务端有重复注册与暴力尝试速率限制、短期挑战防重放、IP 分配冲突防护和设备数量限制。
- 接口：注册设备、公钥更新、创建邀请码、请求配对、查询待审批、双方批准、领取仅属于自己的私网参数、解绑/撤销。定义明确的请求及失败状态，**避免用户扫二维码后无限转圈**。
- 设备解绑、撤销和密钥轮换应立即删除旧 peer/ACL，不再可达。服务器不记录屏幕数据、密钥、完整验证码。

### 数据层：WireGuard VPN

- 当前服务器：Evoxt 日本大阪 VPS；已知公网 IP `166.88.95.233`（部署时复核），拟使用 UDP 51820，先检查现有 x-ui/Reality 与防火墙冲突。
- 每个手机一个独立的 WireGuard 密钥和 100.80.0.0/24 范围内的私网 IP（超出 2 部后需扩容地址计划）。服务端只保留设备公钥和授权的隧道信息。
- FORWARD 默认为拒绝跨设备转发，**仅放行相互确认配对的设备 IP**；严禁直接对公网开放 ADB 或 screen server 端口。仅路由私有叠加网，禁止 0.0.0.0/0 全局代理。
- 服务器上的 x-ui/VLESS Reality 继续独立运行；不要清空 UFW、iptables 或系统路由。部署前备份现有配置。
- 客户端连接显示「配置已下发」「VPN 隧道已启动」「服务端已握手」「ADB 可访问」「观看中」，不要把隧道开启误报为成功观看。

### Android 系统不可绕过的边界

- 首次 Android VpnService 授权必须由用户确认，VPN 指示保持可见。
- 无线调试/ADB 的系统授权不能暗中开启或绕过；手机重启、网络切换、国产 ROM 的 VPN 绑定行为可能限制远程 ADB。
- 保留明确的被观看方同意、断开和撤销入口。不得使用隐蔽录屏、隐藏系统提示或禁用安全提醒来实现。
- 维持只读 scrcpy，**不得加入未经授权的远程触摸、控制、ADB shell**。

## 开发实施顺序

1. 单独实现和测试 VPS 控制服务（可本机运行的服务端测试、负载/滥用限制、服务端配置备份与回滚脚本）。
2. 新增 Android 自动注册模块：生成密钥、HTTPS 认证、配对状态机、错误恢复、设备注销；无明文私钥日志或公开存储。
3. 将用户确认的配对信息与 app 当前 `PairedDeviceStore` 的可信身份关联；兼容旧配置和已配对信息，不擅自覆盖 Beta3 的数据。
4. 将 `MainActivity` 的首次使用流程改为注册/扫码/双方同意，状态可见；确认新流程完整可用后再移除导入入口。
5. 单元/集成测试 + GitHub Actions 构建 Beta4 APK；明确版本号及提交。
6. VPS 现场检查、部署并用两台不同网络的 Xiaomi/vivo 真机验证 WireGuard 握手与已授权 ADB 可达性。
7. 通过断网、退出、重启、拒绝授权、解绑后复连、旧版迁移与服务器回滚测试后才宣布 Beta4 可用。

## 验收

- 全新安装手机的配置过程 **完全没有文件导入/手填 IP**。
- 不同网络扫码配对、双方同意、隧道握手、单向和反向只读观看均经真实手机实测成功。
- 错误状态明确；120 秒内反馈配对/连接结果，用户能取消。
- 安全：未授权设备间无法跨隧道互访；解绑后无法继续建立连接；密钥不被打包或记录；系统 VPN / ADB 授权仍然存在。
- 现有 3X-UI/VLESS Reality 正常；回滚脚本和维护文档齐全。

# 通知专用分支：唯一的通知栏通知

范围：`feature/screensync-notifications-isolated`。此分支中的 Java 应用仅允许创建**一条**通知栏通知：

**「ScreenSync 正在共享屏幕」**，渠道 `screensync_active_share`，ID `8413`，实际截图开始前发布，包含「停止共享」按钮。截图停止后撤销。未共享期间不发布任何 ScreenSync 通知。

## 已移除

- 移除 App 内的“系统通知权限”按钮及手机系统通知状态读数；系统设置仍然拥有最终优先级。
- 观看申请不再发送普通通知，也不会主动弹出 AlertDialog 或悬浮条。原先的单独观看申请通知 ID `8416` 只用于升级后清理历史通知。
- 未共享期间不显示“长期共享已开启”通知或跨应用浮条，后台心跳/网络重连不创建通知。
- 除了明确由用户操作的配对码核对、长期授权、解绑等重要确认对话框外，不主动用弹窗通知用户。

## 用户在本地处理观看请求

长期授权未开启时，来自已配对设备的观看申请显示在 ScreenSync 当前页面里的「收到观看申请」区域，提供「允许本次屏幕共享」与「拒绝本次观看」。不主动弹出；离开页面后也不会通过系统通知唤醒用户。该 UI 不会自动采集屏幕。

## 规范与限制

- 软件内「正在共享通知」开关仅控制该通知；手机系统关闭应用通知或单独屏蔽本渠道时，绝不绕过系统重新发布，软件也不打开系统通知设置或请求权限弹窗。
- 后台在线、配对、心跳、WSS 连接、重连与普通通知权限完全独立。
- 真正跨应用的屏幕采集仍需要设备持有人能够看见并停止该共享。若软件开关或系统设置令唯一可见停止入口不可用，不能继续隐形后台截图；不会创建浮条替代。
- Android 无障碍服务权限和 OEM 系统安全提示是系统级机制，此分支不会尝试移除。
- 静态检查枚举本项目所有 Java `.notify(` 调用，要求仅有一个 `AccessibilityJpegStreamer.java`，并由唯一通知 ID `8413` 发布。

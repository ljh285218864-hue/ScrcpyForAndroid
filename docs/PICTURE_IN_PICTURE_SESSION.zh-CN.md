# ScreenSync Beta 4：可见画中画持续共享（不使用前台服务）

## 目标与实际边界

设备持有人在配对页面同意**当前这一轮**屏幕共享，
并点“继续共享（可见小窗，无前台服务）”，
可让 Android 画中画（PiP）窗口保持可见，不因主页面进入 `onPause` 而立即终止传输。

- PiP 必须是**可见**的小窗，且有“停止共享”动作。
- 普通通知可自行关闭；通知许可不决定媒体是否运行。
- PiP 仅允许已经明确批准并启动本机视频的来源端主动进入。
- 关闭 PiP、离开正常页面、结束会话、撤销配对或 Activity 销毁后即停止采集。
- 新的观看请求仍需设备持有人在普通页面批准。
- 不新增前台服务，不引入 VPN，不隐藏屏幕共享。
- **不能**保证锁屏、小窗被划掉、系统强行停止后继续观看。
- **不能**实现仅凭远端命令，从完全关闭的 App 里无提示自动启动采集。
- 依赖本机 Wi-Fi 无线调试与 ADB+scrcpy 的现有授权，不是无障碍截图架构。

## 手工测试

1. A 和 B 正常完成双向配对与当前会话同意，在 A 页开启视频，B 看见画面。
2. A 点“继续共享（可见小窗，无前台服务）”，观察 A 的 PiP 显示“屏幕正在共享”。
3. B 持续观看，A 进入别的 App，确认在 PiP 小窗保留期间不会因为页面 `onPause` 立即断开。
4. A 用 PiP“停止共享”，或将小窗关闭，确认 B 连接结束、帧不再传送。
5. 在 Android 设置关闭普通通知权限，重复测试；应仅影响普通通知。
6. 锁屏、系统回收、设备重启后均应安全停止旧会话，不会自动重新采集。
7. 真机分别验证 vivo、OPPO、小米 Android 14+ 的 PiP 支持与生命周期。

# ScreenSync 无障碍系统开关自动关闭 — 排查与修复

## 区分状态

| 软件 UI 状态 | 实际含义 | 安全处理 |
| --- | --- | --- |
| 系统开关已关闭 | Android 已不将 ScreenSync 列为已开启的无障碍服务 | 设备持有人手动打开系统无障碍设置；软件不代开 |
| 系统已开启但服务未连接 | Android 已启用该服务，但 `onServiceConnected` 暂未建立连接 | 检查后台限制、是否被系统终止以及日志 `service_destroyed` / `service_unbound` |
| 系统已开启、服务已连接 | 无障碍服务正常连接 | 如仍共享失败，另查共享状态通知、网络与截图结果 |

状态由 `AccessibilityManager.getEnabledAccessibilityServiceList` 只读判断，不写入 `Settings.Secure`、不调用 ADB/Shizuku/root，不自行重开无障碍。

## 安装更新问题

GitHub workflow 当前调用 `assembleScrcpyDebug`，没有固定签名配置。托管 Runner 的自动生成调试密钥通常每次不同，因此不同 CI 产物无法保证覆盖安装。卸载旧版重装会清除 Android 原有无障碍授权及本地配对数据；若要长期稳定升级，必须配置同一把用户掌握的私有签名密钥，并在 CI 以受保护的 GitHub Actions Secret 使用。绝不能把 keystore / 密码提交到仓库。

如果已经出现签名不兼容，不要通过改包名或自动申请特殊权限绕过；需要先建立固定签名后再做一次明确的迁移安装。

## 手机系统优化（由用户自行选择）

打开 Android 应用信息，检查“电池使用/后台运行/允许自启动”、“闲置应用自动移除权限”以及安全中心的自启动白名单；仅在本人理解耗电与安全影响后设为允许。系统不保证进程永久存活，强行停止或厂商安全策略仍能结束服务。

Android 13+ 的手动安装 APK 可能受到“受限制的设置”保护；必须由持有人在系统应用信息页面理解风险并确认。不要把它当作自动续权手段。

本补丁只增加应用内状态诊断及本人主动打开的排查对话框，保持当前唯一的实际共享通知和 STOP 操作；不增加后台常驻通知或自启截图。

# 局域网唤醒 + 只读屏幕同步（测试阶段）

> 该功能是 **LAN 测试链路**，不是正式的异地配对或跨公网解决方案。
> 任何被观看手机均须属于自己或由持有人明确授权。

## 当前实现

- A 和 B 均安装相同 APK，两个方向使用相同的功能。
- A 主动在「更多设置」开启接收，生成临时随机 128 位密钥，启用带可见通知的 connectedDevice 前台服务。
- A 的 TCP 10055 端口接收局域网唤醒请求，只接受 RFC1918 私网或 loopback 来访。
- B 通过挑战应答 HMAC-SHA256 证明自己持有临时密钥；请求内不会传输明文密钥，且服务端挑战随机生成。
- 正确密钥得到 ACK，A 记录接收时间并发布「收到屏幕观看请求」通知。
- **只有 ACK 成功后，B 才尝试通过先前已获系统授权的 ADB 连接启动只读 scrcpy 视频。**
- B 对远端屏幕的点击、滑动、按键、命令操作仍然全部禁止。
- A 可关闭唤醒接收以阻止后续新请求；此操作 **不能自动撤销已有 ADB 连接**。要阻止当前已授权的 ADB 会话，应在 A 系统设置中关闭无线调试并撤销相关调试授权。

## 两台真机如何测试

1. A、B 处于同一可互访的局域网，A 通过开发者选项开启无线调试，并由 A 的持有人确认 B 的 ADB 调试授权。注意无线调试端口不一定是 5555。
2. A 打开 App →「更多设置」→「A手机 · 开启接收」，在本机复制显示的 **32 位临时测试密钥**。接收期间可见常驻系统通知。
3. B 打开 App，填写 A 的 **ADB 连接地址和真实端口**；在「更多设置」中另外填写 A 的局域网 IP **:10055** 和刚才的密钥。
4. B 点击「开始观看屏幕」。程序先向 A 发送带密钥证明的唤醒请求；收到 ACK 后，B 尝试恢复 ADB 连接并启动 scrcpy 只读画面。
5. 测试 B 关闭再打开观看；测试 A 按 Home 后是否仍可接收新请求。部分系统划走后台任务会结束服务，不能保证后台运行。
6. 停止接收新请求：A 点击「A手机 · 停止接收」。停止 **已有** 同屏则需关闭 ADB 无线调试/撤销调试授权，或由 B 主动断开观看。

## 限制

- A 未主动开启接收、测试密钥错误或 ADB 未获授权时，B 不会成功开启观看。
- **此服务无法从完全被杀死/强行停止的 App 自动复活**；手机重启后不保证自动恢复，ADB 连接可能需重新启用或授权。
- 不支持公网穿透，不应直接将 TCP 10055 或 ADB 调试端口暴露在互联网。异地安全连接需要后续建立身份认证与安全传输/中继链路。
- 唤醒信令服务不采集画面、不唤醒或解锁屏幕。视频由原来的 ADB/scrcpy 实现启动，必须保持 ADB 授权。
- Android 14/15 模拟器测试不等于真实 vivo/OPPO 测试。实际后台限制、无线调试持续性需要真机验证。
- 当前使用临时测试密钥，不是正式双方配对流程。正式版需要密钥撤销、配对确认、设备身份绑定、端到端安全连接和查看状态。

## 自动化验证

- `Wake Signal Protocol Fast Check`：Java HMAC、错误密钥拒绝及脚本语法。
- `Dual Android 14/15 Emulator Test`：A 明确启动接收后后台运行；错误证明拒绝；B 发送正确认证请求；随后已有授权的 ADB 建立 scrcpy 视频，并比较 A/B 画面。
- 以 Actions 的实际状态为准，不把“构建成功”当成“真机同屏全部通过”。

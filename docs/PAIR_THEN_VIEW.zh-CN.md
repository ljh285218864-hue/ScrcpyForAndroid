# 局域网首次配对 → 后续只读观看（开发测试版）

## 现在的操作入口

两台 Android 手机安装同一 APK，并连接可互访的 Wi-Fi。

1. **A 手机**打开 App，点「让其他手机与我配对（显示配对码）」。屏幕显示 **6 位一次性 App 配对码**，3 分钟有效；A 的可见接收通知会开启。
2. **B 手机**点「搜索附近手机并配对」，选择 A 手机，输入 A App 显示的 6 位码。**A 必须在自己的手机上点「允许配对」**，否则 B 无法获得长期配对凭证。成功后双方私有存储里记录一对一设备凭证，不再重复输入 App 配对码。
3. **首次系统无线调试授权（仅在未授权时）**：A 在系统开发者选项 → 无线调试 →「使用配对码配对设备」打开系统配对界面。B 点「首次系统无线调试授权」→「已打开，自动查找」，App 自动发现系统配对端口；B 只填写**系统**显示的 6 位码。注意这**不是**第 1 步的 App 配对码。ADB 端口和授权取决于手机系统，不能绕过/静默开启。
4. B 点「搜索附近手机并配对」重新发现 A 的无线调试**连接端口**（不用手动输入 IP），选回已配对的 A，或回首页按「观看已配对手机」，会先使用保存的设备密钥发送唤醒请求，成功后通过已授权的 ADB 启动只读 scrcpy 画面。
5. 以后 A 还在接收并且系统无线调试仍可用时，B 可点击「观看已配对手机」。如果手机 IP 改了，先「搜索附近手机并配对」；只有通过旧配对密钥验证的设备才允许更新连接地址。

## 系统限制 / 安全边界

- **App 配对 ≠ 系统 ADB 配对**：必须完成 Android 的无线调试授权才能启动 scrcpy。普通无 Root 手机不可能通过 App 自行打开无线调试或绕过系统授权。
- A 每次开启接收都有明显通知，进入配对必须显式操作且在 A 端批准。A 可点「解除本机配对」清除 App 密钥、停止接收；若要撤销此前的 ADB 授权，还需在 A 的系统设置中清除已配对调试设备。
- 当前仅同一可互访局域网，不支持不同网络、后台被强制停止后的保证唤醒，也不保证系统重启后无线调试仍启用。
- **目前仅一对一应用信任记录**；AB 角色可互换，但反向看 B 的屏幕还必须由 B 开启接收并完成针对 B 的系统 ADB 调试授权。
- 当前一次性短码配对协议是**局域网测试实现**，仍需加强安全传输和真机抗干扰测试后才能对外正式发布。
- 不要把 ADB 无线调试端口或 TCP 10055 暴露在公网。视频端仍保持只读，不执行远程按键、触摸或任意 shell。
- 已提交 Java 协议的本地模拟测试，但**新版完整 APK 构建、Android 14/15 双机配对与小米 / vivo / OPPO 真机验证尚待确认**，不要把“代码已提交”当作“正式功能已验收”。
